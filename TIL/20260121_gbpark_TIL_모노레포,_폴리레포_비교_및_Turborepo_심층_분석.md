## 📚 학습 주제
🚀 모노레포 (Monorepo) 개념과 주요 도구

---

## 🔑 핵심 내용
- 모노레포는 **중앙 집중형 코드 관리 전략**으로, 효율성 극대화와 공유, 일관성 추구에 중점을 둡니다.
- **폴리레포(Polyrepo)**는 분산형 관리를 통해 독립성과 안정성 극대화를 목표로 하며, 모노레포와 대비되는 특징을 가집니다.
- `pnpm workspace`, `Turborepo`, `Nx`는 모노레포 환경을 효과적으로 관리하기 위한 대표적인 도구들입니다.
- 특히 **Turborepo**는 고성능 빌드 시스템으로, 증분 빌드, 콘텐츠 기반 해싱, 클라우드 캐싱 등을 통해 빌드 시간을 최적화합니다.
- **거버넌스(Governance)**는 목표 달성을 위한 의사결정 과정 및 이행 전체를 아우르는 시스템으로, 모노레포 환경에서도 중요한 개념입니다.

## 📝 상세 내용

### 🌐 모노레포 vs. 폴리레포 비교

| 분류          | 모노레포 (Monorepo)                                                                                                              | 폴리레포 (Polyrepo)                                                                                                                              |
| :------------ | :------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------- |
| **가치 추구** | 효율성 극대화, 공유 및 일관성                                                                                                    | 안정성 극대화, 분리 및 독립성                                                                                                                    |
| **특징**      | - 중앙 집중형<br>- 공유 코드 및 규칙<br>- 동기화/버전 통합 관리<br>- 개발팀의 빠른 속도 및 높은 집중도                              | - 분산형<br>- 독립 코드 및 설정<br>- 저장소 간 동기화/버전 관리 부담<br>- 부분적인 실패가 전체로 확산되지 않도록 격리                       |
| **권한/거버넌스** | - 조직 전체에 접근 권한 부여<br>- 코드 리뷰/정책 일괄 적용                                                                      | - 저장소별 권한 분리<br>- 팀별 릴리즈/정책 독립 운영<br>- 조직 전반의 표준화/통합 관리 어려움                                              |
| **적합 환경** | 비즈니스 가치에 집중해야 하는 빠른 개발 환경                                                                                     | 금융, 인프라, 공공 서비스와 같이 안정적인 운영이 중요한 프로젝트                                                                                 |

### 🛠️ 주요 모노레포 도구

#### 1. pnpm workspace
- **효율적인 의존성 관리**: 의존성을 한 번만 설치하고 여러 프로젝트가 공유하여 디스크 공간을 절약하고 설치 속도를 빠르게 합니다.
- `pnpm-workspace.yaml` 파일 하나로 간단하게 설정할 수 있어 도구 학습 부담이 적습니다.

#### 2. Turborepo
- **빌드 성능 최적화**: 복잡한 기능보다는 빌드 속도 최적화에 중점을 둡니다.
- **지능적인 빌드 캐싱**: 이전에 빌드된 결과를 재사용하고, 태스크(작업) 간의 의존성을 자동으로 분석하여 가능한 모든 작업을 최대 병렬로 실행합니다.
- **원격 캐시**: CI/CD 환경에서 팀원 간 또는 빌드 간 캐시를 공유하여 빌드 시간을 더욱 단축할 수 있습니다.

#### 3. Nx
- **엔터프라이즈급 모노레포 관리 프레임워크**: 구글의 Angular 출신 개발자들이 개발했습니다.
- **다양한 기술 스택 지원**: React, Vue, Node.js 등 여러 기술 스택을 지원합니다.
- **강력한 성능 최적화**: 지능형 캐싱과 병렬 빌드를 제공하며, 시각화된 의존성 그래프를 통해 프로젝트 구조를 쉽게 파악할 수 있습니다.

### 🚀 Turborepo 심층 분석

Turborepo는 JavaScript, TypeScript 코드 베이스의 모노레포를 위한 고성능 빌드 시스템입니다.

#### Turborepo의 핵심 특징 (9가지)
1.  **Incremental Builds (증분 빌드)**: 작업 진행 상황을 캐싱하여 이미 계산된 내용은 건너뛰고, 빌드는 딱 한 번만 하는 것을 목표로 합니다.
2.  **Content-aware Hashing (콘텐츠 인식 해싱)**: 타임스탬프가 아닌 콘텐츠를 인식하는 방식으로 해싱을 지원하여, 모든 파일을 다시 빌드하는 것이 아니라 변경된 파일만 빌드합니다.
3.  **Cloud Caching (클라우드 캐싱)**: 클라우드 빌드 캐시를 팀원 및 CI/CD와 공유하여 로컬 환경을 넘어 클라우드 환경에서도 빠른 빌드를 제공합니다.
4.  **Parallel Execution (병렬 실행)**: 모든 코어를 사용하여 병렬 실행을 목표로 하며, 지정된 태스크 단위로 의존성을 파악해 최대한 병렬적으로 작업을 진행합니다.
5.  **Task Pipelines (태스크 파이프라인)**: 태스크 간의 연결을 정의하여 빌드를 언제 어떻게 실행할지 판단하고 최적화합니다.
6.  **Zero Runtime Overhead (제로 런타임 오버헤드)**: 런타임 코드와 소스 맵을 다루지 않기에 런타임 단계에서 파악하지 못한 리스크가 생길 위험이 없습니다.
7.  **Pruned Subsets (가지치기된 부분 집합)**: 빌드에 필요한 요소만으로 모노레포의 하위 집합을 생성하여 PaaS 배포 속도를 높입니다.
8.  **JSON Configuration (JSON 설정)**: 별도의 코드 작업 없이 JSON으로 Turborepo를 설정하고 사용합니다.
9.  **Profile in Browser (브라우저 프로필)**: 빌드 프로필을 통해 빌드 과정을 시각화하여 병목 지점을 쉽게 찾을 수 있습니다.

#### `turbo.json` 설정 파일 분석

Turborepo는 `turbo.json` 파일을 사용하여 파이프라인을 정의합니다.

```json
{
  "$schema": "https://turbo.build/schema.json",
  "globalDependencies": ["pnpm-lock.yaml"],
  "tasks": {
    "build": {
      "dependsOn": [
        "lint",
        "check-types",
        "@app3#build",
        "@app2#build",
        "@app1#build",
        "@app4#build"
      ],
      "inputs": ["$TURBO_DEFAULT$", ".env*"],
      "outputs": ["dist/**"]
    },
    "lint": {
      "dependsOn": ["^lint"]
    },
    "check-types": {
      "dependsOn": ["^check-types"]
    },
    "@app3#build": {
      "outputs": ["../../dist/**"]
    },
    "@app2#build": {
      "dependsOn": ["@app3#build"],
      "outputs": ["../../dist/app2/**"]
    },
    "@app1#build": {
      "dependsOn": ["@app3#build"],
      "outputs": ["../../dist/app1/**"]
    },
    "@app4#build": {
      "dependsOn": ["@app3#build"],
      "outputs": ["../../dist/app4/**"]
    }
  }
}
```

-   **`tasks`**: 모노레포 내에서 실행할 모든 작업을 정의하는 객체입니다. `build`, `lint`, `check-types`와 같은 공통 작업과 함께 `@app1#build`와 같이 특정 워크스페이스(`@app1`)에 특화된 빌드 작업들을 명시합니다. `@app1#build`는 해당 패키지의 `package.json`에 정의된 `build` 스크립트를 실행하라는 의미입니다.
-   **`dependsOn`**: 특정 작업을 실행하기 전에 반드시 먼저 완료되어야 하는 작업들을 지정합니다. 예를 들어, `build` 작업은 `lint`, `check-types` 그리고 각 애플리케이션의 빌드 작업이 먼저 성공적으로 끝나야 실행됩니다. 이 작업들은 병렬로 실행되며, 하나라도 실패하면 상위 작업인 `build`는 실행되지 않습니다.
-   **`inputs`**: 캐싱을 결정하는 기준 파일들을 명시합니다. `$TURBO_DEFAULT$`는 Turborepo가 자동으로 캐싱에 포함하는 기본 파일들을 의미합니다.
-   **`outputs`**: 빌드 결과물이 저장되는 경로를 지정합니다. 해당 경로의 파일은 캐시로 저장되거나 복원하는 데 사용됩니다.

**사용법**: 모노레포의 루트 디렉터리에 `turbo.json` 파일을 생성한 후 파이프라인을 작성합니다. 파이프라인의 각 명령어들은 하나의 태스크 단위이며, 이 단위가 병렬 처리 및 의존성의 범위가 됩니다.

## 💡 새롭게 알게 된 점
- **거버넌스(Governance)**의 정의: 과거 일방적인 정부 주도적 경향에서 벗어나 정부, 기업, 비정부기구, 시민단체 등 다양한 행위자가 공동의 관심사에 대한 네트워크를 구축하여 문제를 해결하는 '참여형 국정운영의 방식' 또는 '새로운 행정 시스템'이나 '정부 경영 전략' 등을 의미합니다. 통치, 관리를 넘어 목표 달성을 위한 의사결정 과정 및 이행 전체를 아우르는 시스템이라는 점을 명확히 이해했습니다.
- **Turborepo의 `content-aware hashing`**: 단순히 파일의 타임스탬프가 아닌 실제 콘텐츠 변경 여부를 기반으로 캐싱을 결정한다는 점이 매우 효율적이며, 불필요한 재빌드를 최소화하는 핵심 메커니즘임을 알게 되었습니다.
